# 采集与运维配置

## 主机采集与历史

总览汇总全部节点的状态，并为每个节点显示最近一次采样的 CPU、内存和磁盘使用率以及采样时间。磁盘使用率取有容量数据的挂载点中的最高值。

节点详情展示 CPU、负载、内存、Swap、挂载点和网络接口。采集使用 Agent 所在 Linux 实例的视角。WSL 页面显示 WSL 的观察结果。宿主机标识可手动关联，Windows 状态需要独立观测。首次速率和计数器重置之后可能暂时缺测，趋势按观测时刻保留空档。主机指标定时采集。进程、Docker 和 systemd 的实时查询共享另一组并发配额。

中心支持以下环境变量。配置修改后重启中心，Agent 重连时获取采样间隔。面板「设置」显示生效值。

| 环境变量 | 默认值 | 范围 |
| --- | --- | --- |
| `ASTERION_SAMPLE_INTERVAL_SECS` | 15 秒 | 5～3600 秒 |
| `ASTERION_METRIC_RETENTION_DAYS` | 7 天 | 1～365 天 |
| `ASTERION_TREND_RETENTION_DAYS` | 90 天 | 30～365 天 |

## 按需纳管与服务资产

「节点」代表通过 Agent 接入的 Linux 或 WSL 环境。进入节点详情，在进程、Docker 或 systemd 页签选择「添加监控」，搜索目标并点击「纳管」。各页签默认显示该节点已选定的对象。清单保存在中心，换浏览器或节点暂时离线时仍可查看。

- 进程按 Linux 进程名称精确匹配同名实例。重启并产生新 PID 后，只要名称一致就会继续显示。详情最多显示 12 个实例，按 PID 升序排列。进程详情可在观测到控制组归属时显示 systemd Unit 或容器 ID。
- Docker 容器按 Engine ID 和完整容器 ID 匹配。重建容器会生成新 ID，请纳管新容器并取消旧记录。容器详情提供启动时间、健康状态、资源使用和受限日志。
- 中心按当前清单页刷新实时状态，只返回纳管名称匹配的进程实例和 Engine ID、完整容器 ID 均匹配的容器。取消纳管只移除该监控记录。systemd 的持续检查与告警由中心后台执行。

「资产」是手工维护的服务目录。每项资产归属于一个部署节点，可记录部署路径、配置和代码仓库，并绑定同节点的发现实例。绑定能帮助定位部署对象。监控配置在节点详情独立设置。

## 单个 systemd 服务监控

在节点详情的 systemd 页签选择「添加监控」，按 Unit 名称查找并纳管。每个节点最多可启用 16 个具体的 `.service`，适合预期持续处于活动状态的服务。中心使用 Agent 的只读查询能力，目标检查间隔为 15 秒。检查时间会随节点负载和调度变化。

同一页签的「已纳管 systemd 服务」列表显示最近检查时间和状态。打开 Unit 的「状态历史」可查看最近 50 条变化。Agent 离线时仍可查看已有记录。首次检查前显示待检查。`active`、`reloading` 和 `refreshing` 表示健康，`inactive` 和 `failed` 表示停止。过渡状态、Agent 离线或读取失败时显示未知。已有的服务告警会保留到确认恢复或停用监控。[systemd 状态定义](https://www.freedesktop.org/software/systemd/man/latest/systemctl.html)

确认停止后，总览和告警页显示带节点和 Unit 名称的「服务停机」告警。确认服务恢复活动后，原告警标记为「已恢复」。在服务详情选择「停用监控」后，已有告警标记为「监控已停用」，勾选「显示已停用」可以查看历史或重新启用。状态变化、已结束的告警和停用记录按 `ASTERION_TREND_RETENTION_DAYS` 清理，默认保留 90 天。活动告警保留至结束。

## Docker

默认关闭 Docker 读取。需要监控时先配置独立的 Unix Socket 读取服务，再给 Agent 设置 `ASTERION_DOCKER_READER_SOCKET`。读取服务所在账号需要 Engine Socket 权限。面板展示独立 Docker Engine、Docker Desktop 或未知类型。中心按观测节点记录 Engine ID 和端点指纹，空容器列表也会保存 Engine 身份。容器日志仅取有限条数和字节，按常见敏感文本规则尽力脱敏。Docker 环境变量值默认不采集。

Docker 变更使用独立的操作 Socket。其策略同时限定 Engine ID、完整容器 ID 和支持的动作。两个 Socket 的访问组应分别配置。安装步骤见[远程部署](deployment.md#8-启用可选能力)。

## 受控任务

节点的「软件安装」「服务配置」以及 Docker 页的「容器服务」独立授权；通用预定义命令不代替这些入口。未授权时仍可监控。配置方式、恢复和限制见[节点操作](managed-operations.md)。systemd 清单可直接准备启停任务，任务完成后读取服务实际状态。

默认 Agent 未加载运维策略。启用时，将[策略样例](../deploy/executor.example.json)复制到受保护的配置目录，删除不使用的能力并替换占位符，设置 `ASTERION_EXECUTOR_CONFIG_FILE` 后重启 Agent。预定义命令使用绝对可执行路径和类型化参数，参数校验在节点侧执行。systemd 白名单登记具体的 `.service` 名称，包含 `\xHH` 转义的实例名称须按 systemd 显示的完整名称填写。[systemd Unit 命名规则](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html)

在相应容器、Unit、进程或预定义命令处发起任务，核对节点、目标和动作后确认。进程信号按 PID 和启动标识核验，KILL 需要重新验证管理员口令。运维页展示状态、已收到的输出、耗时和审计。在发起任务的登录会话中确认或取消任务。确认和取消采用异步处理，页面随后读取任务状态。预定义命令的子进程须留在任务进程组，取消和超时会清理该组。已经应用的服务状态变更需要通过后续操作恢复。受控本地命令要求支持 seccomp 的 Linux x86-64 或 AArch64。

## Linux 账号和公钥

Agent 按本机权限读取用户、组和授权公钥的指纹。普通账号的创建、附加组与公钥变更通过独立的本机账号操作服务启用。目标账号和可管理组来自本机策略。管理员确认目标并重新验证口令后才会提交。修改附加组和公钥之前，账号操作服务会在配置的私有目录分别备份组清单和原授权文件。受保护账号、特权组和系统 SSH 配置保留给现有主机运维流程。使用部署示例的家目录隔离时，经账号操作服务读取授权公钥需要将目标加入该服务的账号白名单。

账号变更失败时，在目标主机先检查账户及家目录是否已创建、附加组是否已生效，或公钥指纹是否已变化。需要恢复时，按任务时间和用户名在 `backup_dir` 选择对应文件。`<用户名>.groups.*.backup` 是变更前的附加组清单，仅恢复本次受管组的变更，保留后续独立调整的组成员资格。`<用户名>.authorized-keys.*.backup` 是变更前的授权文件，核对差异、文件归属和权限后恢复对应条目。公钥备份留在目标主机的私有目录。

## 终端、告警和趋势

交互终端通过独立的本机 Unix Socket 服务运行。先为终端配置专用非 root 账号及单独的访问组，再让中心和 Agent 设置 `ASTERION_TERMINAL_ENABLED=1`。Agent 通过 `ASTERION_TERMINAL_HELPER_SOCKET` 连接终端服务，并检查对端 UID 与 Socket 目录归属一致，且区别于 Agent UID。终端服务账号只拥有终端 Socket 访问权限。中心使用受限私网入口，每次建立会话前复核管理员口令。每节点支持一个会话。退出面板时，中心立即收回该登录会话的终端访问权限，并通知 Agent 关闭相关终端。终端空闲 2 分钟或到达 15 分钟后关闭。多行粘贴需在面板确认。屏幕内容不入库。部署步骤见[远程部署](deployment.md#交互终端和保留周期)。

节点告警规则可按 CPU、内存、磁盘利用率或 Agent 离线条件配置持续时间。面板合并展示节点告警和已开启监控的 Unit 告警，并保留各自的开始与结束时间。长趋势使用五分钟聚合，支持最近 7 天及 30 天。告警及长期趋势不依赖外部 SaaS。
